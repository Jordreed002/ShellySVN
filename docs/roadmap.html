ShellySVN shipped its first stable 1.0.0 in May 2026 and is now in the 1.1.0 beta (auto-update & release infrastructure). 📌 Status: v1.1.0-beta (current) — 1.1.0 GA next 🗓 Revised: 2026-07-31 🔀 Cadence: time-boxed minors, stabilization-first
Vision

Inspired by TortoiseSVN, rebuilt for today.

Subversion is still the right tool for many teams — yet its clients have stagnated. ShellySVN replaces decades-old UI with a modern, virtualized, keyboard-first desktop app that bundles its own verified SVN binary so it "just works." With a stable 1.0 out, the focus shifts from "make it exist" to "make it the most trustworthy, accessible, and complete SVN client on any platform."

Trust & safety first

An unobtrusive client must never be the weak link. Hardened process boundaries, encrypted credentials, and data-safe operations come before features.

Fast at any scale

Working copies with hundreds of thousands of files should feel instant. Virtualization, incremental status, and background indexing are non-negotiable.

Accessible by default

A developer tool is only "modern" if everyone can use it. WCAG-grade keyboard navigation, focus management, and screen-reader support are release gates, not afterthoughts.

Guiding principles

How we decide what goes in each release.

When work competes for a release window, these principles break ties — in order.

1 · Correctness over features

A bug that corrupts a working copy or leaks credentials blocks a release; a nice-to-have feature does not. Security fixes ship as patches without waiting for a themed minor.

2 · Subversion fidelity

We wrap the real svn CLI faithfully — no reinvented semantics. TortoiseSVN-class workflows are the parity bar.

3 · Cross-platform parity

macOS and Windows are first-class; Linux is a close second. A feature isn't "done" until it works everywhere we ship.

4 · Performance is a budget

Bundle size and large-list performance are enforced in CI. Regressions fail the build, not just the review.

5 · Small, shippable minors

Time-boxed releases that each deliver one clear theme. Momentum over monoliths.

6 · Backward-compatible 1.x

1.0 established the stability promise; 1.x minors stay backward-compatible so users can auto-update without fear.

Versioning philosophy

What the version number promises.

ShellySVN follows semantic versioning. 1.0.0 shipped in May 2026 and established the stability promise; from here, the 1.x line stays backward-compatible.

1.x.Y · patch

Fixes & security

Bugfix or security fix only; all tests green; no new behavior. Critical security fixes ship here as soon as ready, not gated on a minor.

1.X.0 · minor

One theme, backward-safe

Additive, compatible features behind a single release theme. Each meets its exit criteria; typecheck + lint + boundaries + coverage + build all green in CI; changelog written.

2.0.0 · vision

Bigger bets

Exploratory, larger-scope directions (sync, automation, companions) that may shift behavior. Only items validated during 1.x graduate into 2.0 — nothing committed yet.

Release cadence

Proposed: one minor every ~6–10 weeks, with patches as needed. A release may slip if it isn't ready — but a release never ships before its exit criteria are met. Dates below are proposed targets, adjustable as we learn.

Milestones

Goals & milestones, by version.

The near-term milestones are grounded in the project's own audits — the security & correctness review and SVN_IMPLEMENTATION_TODO.md (P0 data-safety → P3 missing features). Because 1.0 is already out, hardening lands as a fast-follow minor (1.2), with critical fixes shipping as patches.

1.1.0

Update Infrastructure — GA

Ship the beta to a general-availability release.

Current · betatarget 2026 Q3

Goal: promote user-approved auto-update and the stable/preview channel model from beta to GA, with signed artifacts on every platform.

Finish & ship
  • GA auto-update: Windows NSIS, signed macOS, Linux AppImage
  • Stable + opt-in preview release channels live; updater metadata/blockmaps validated
  • Enforce version-match (git ↔ package) & signed Windows/macOS artifacts as a release gate
  • Check-for-Modifications inspector (local vs repository status) shipped
  • Mac notarization / Windows code-signing green on the release pipeline
Exit criteria1.1.0 promoted to stable; auto-update proven end-to-end on all three platforms; no release can publish without signed artifacts.
1.2.0

Security & Hardening

Close the boundary gaps a shipped 1.0 can't carry.

Next plannedtarget Q4 2026

Goal: close the security boundary and eliminate data-safety risks found in the code review. Critical fixes backport to 1.1.x patches immediately.

Security boundary
  • Replace the unfiltered ipcRenderer bridge with a channel allowlist (only curated window.api)
  • Fix app:getPath self-approving $HOME into the approved-paths registry
  • Gate fs:readImageAsBase64 through the approval check like every sibling handler
  • Validate external diff/merge tool paths (whitelist + Settings-registered custom tools; reject arbitrary executables)
  • Validate the custom-editor setting in updateSettings; never shell:true custom paths
  • Write auth/config/approved-paths files mode 0o600; validate SVN prop/changelist/shelve names
Correctness & runtime
  • Zombie-safe process teardown: process-group kill + SIGTERM→SIGKILL escalation on cancel/timeout
  • Monitor interval: re-arm on completion, unref(), clear on quit; normalize path on removeWorkingCopy
  • Consistent tagged error envelope across SVN handlers (no more as T)
  • Upgrade Electron 33 → current (33 is end-of-life; missing Chromium/V8 security patches)
  • Build the CLI entrypoint declared in package.json bin (currently never produced)
  • Close P0 data-safety items from SVN_IMPLEMENTATION_TODO.md
Exit criteriaTargeted security re-review clean; zero open P0 data-safety items; CLI builds & runs; on a current Electron.

Usable for everyone; pay down UX debt.

  • Fix the focus-trap overlay-click-to-close bug

  • ARIA + keyboard submenu support for Command Palette & Context Menu; restore file-list grid semantics
Code health & perf basics
  • Stable-identity fixes so FileRow memoization actually works (folderSizes, handleSelect)
  • Fix virtualization in fileListHeight:'auto'
  • Resolve the dead operation queue (delete, or wire it in for real cancellation)
  • Fix repo-browser cache-invalidation scope + the :shelves key mismatch

Stay fast on the largest working copies.

Plannedtarget Q2 2027

Risk & mitigation

What could derail the plan.

The biggest uncertainties, and how each is bounded.

High

Known gaps in a shipped 1.0

The security review found real boundary holes in a product already at 1.0. Mitigation: critical fixes ship as 1.1.x patches immediately; the structural work is the 1.2 hardening minor with a re-review gate.

High

Bundled-SVN maintenance across platforms

Shipping a verified per-platform SVN binary is a standing burden. Mitigation: keep verify:binaries as a hard build gate; track upstream SVN; consider a shared binary pipeline.

Medium

Scope creep on the 1.x line

Feature requests will compete with hardening/a11y. Mitigation: the versioning philosophy makes correctness > features explicit, and each minor has written exit criteria.

Medium

Electron major-version churn

Electron's cadence forces periodic migrations. Mitigation: a planned bump per cycle (1.2 → current) rather than emergency jumps; CI runs real-SVN workflows on all platforms.

Low

Auto-update trust

Users must trust updates once they're automatic. Mitigation: 1.1 user-approves updates, signs every artifact, and separates stable vs preview channels.
