Repository browser, refined — current

Taken apart against how SVN actually behaves, and what teams now expect
Light + dark · supersedes 11 · six targeted refinements

11 was coherent but quietly wrong in one place and silent in several others. Each change below answers something Subversion actually does.

  • TruthTwo sources, visibly separate. svn ls describes the server; svn status describes your disk. They only overlap inside a checkout — so status columns and roll-ups now appear only there, with a scope chip in the footer naming which you're looking at. And presence is marked rather than absence: 2 of 51 clients read “partly checked out” instead of 46 reading “not checked out”.
  • DiffIt says what it's comparing. A comparand control offers WC↔BASE, WC↔HEAD, BASE↔HEAD, branch↔trunk, rev↔rev — and explains the consequence (“incoming changes only — your edits are not in this diff”).
  • MixedMixed revisions are shown. A working copy isn't “at r4821” — it holds files between r4744 and r4838. A strip in the band makes the range visible. No client does this, and it's why svn status confuses people.
  • MergeEligible revisions, not just “merge”. mergeinfo answers what's on trunk and not here yet — 4 revisions, listed, one flagged because it touches a file you've edited. Sync vs reintegrate vs record-only are distinguished, with a dry run first.
  • UglyA Problems surface. Tree conflict, needs-cleanup, stale lock, floating external — the frequent, baffling states, each with cause, consequence and the command.
  • ModernHonestly mapped. No pull requests in SVN, so review runs on shelves (svn shelf). Build status and issue references ride the log via bugtraq: properties.

Repository browser — superseded by 12

No projects · no modes · one vocabulary — Subversion's
Light + dark · Archivo / JetBrains Mono · supersedes 08–10

Subversion has directories, so this has directories. It also has one vocabulary, used precisely everywhere — checkout, update, commit, switch, revision, BASE, HEAD, depth, externals, conflicted — with the status word and its code shown together (Modified M).

  • SearchRepository-wide path search replaces the project finder — flip the scope chip and the contents pane lists matches from all 512k paths with their location.
  • BridgeA working-copy banner appears whenever you browse a path you have on disk: local path, BASE vs HEAD, modified/conflicted counts, and Update / Commit / Reveal.
  • TimeAn @revision peg in the address bar — browse the whole tree as it was at r4835 or a date, with the bar tinted so you can't forget you're in the past.
  • DetailA permanent pane with Diff · Blame · Log · Properties. Blame marks uncommitted lines; ⌥D / ⌥B from any row.
  • BulkSpace to multi-select, with an action bar for Checkout / Export / Copy URLs. Deep paths collapse in the middle of the breadcrumb.
  • Keys⌘[ ⌘] ⌘↑ ⌘L ⌘K / plus arrows and type-ahead — Explorer/Finder parity throughout.

Atlas — superseded by 11

Projects on top of plain SVN · one explorer · developer mode = code tools
Light + dark · Archivo / JetBrains Mono · supersedes 09

Answers the honest question: Subversion has no concept of a project. It only stores folders. So a project here is a lens Shelly infers or is told about, and it degrades to plain folders when nothing applies.

  • ProjectsFour sources, in order: a versioned folder property (shelly:project), a repo config file (/.shelly/projects.yml), convention — a folder containing trunk — and your own working copies. A chip in the header says which one applied, and any folder can be promoted or demoted by hand.
  • WordingThe plain phrasing and the technical facts are now both always on — paths, revisions, sizes and status codes sit alongside “Edited”, “Needs you”, “Current work trunk”. No vocabulary is hidden from anyone.
  • Dev modeNo longer changes words — it promotes the code tools. A third pane appears with Diff / Blame / History, selecting a changed file opens its diff immediately, every file row grows Diff and Blame buttons, and ⌥D / ⌥B jump straight there.
  • ExplorerEverything from 09: expandable tree, sortable contents, back/forward/up, typable address bar, search-this-folder, type-ahead, status roll-ups, download state. Columns shed automatically when the diff pane takes the width.

Atlas Lite — superseded by 10

Find a project, not a path
Light by default, dark on a switch · Archivo / JetBrains Mono · accent #2563c9

08 simplified so a non-technical person can use it. Same repository, same facts — but it opens on a searchable directory of every project, grouped by client, instead of a wall of columns.

  • ExploreA real file explorer, and it genuinely works — expandable tree, sortable contents, back / forward / up, a breadcrumb that doubles as a typable address bar (⌘L), search-this-folder, and keyboard nav with type-ahead. Rendered from a live model of 51 clients and their nested projects.
  • ScaleBig folders say so — “Showing 14 of 1,240 — use search to narrow it down”, “… 39 more — search instead” in the tree, spinners on unlisted folders. Status roll-ups put 11 changed · 1 needs a decision on clients/ at the root.
  • TwoTwo regions, never four. A finder, then a project. Inside a project it's the familiar folders-left / contents-right browser, not Miller columns.
  • Wordstrunk / branches / tags collapse into one “Version” menu — “Current work”, “Work in progress · Payments v2”, “Released · v3.1.4”, each with a sentence explaining it.
  • StateDownload state in plain words — “On your computer”, “Partly downloaded”, “Not downloaded” — with a disk card: “You keep only the projects you work on.”
  • SwitchOne “Developer details” toggle brings back paths, URLs, revision numbers, depth, sparse-checkout editing and the svn command under every menu item. Nothing is removed from the product, only from the first screen.
  • Get“Get a copy” instead of Check out — with size and “about 3 minutes” rather than depth jargon. The per-subtree depth table appears only in developer mode.

Atlas — monorepo navigator

The repo browser, rethought for 50 clients and 2.1 TB
Dark · Archivo / JetBrains Mono · TortoiseSVN repo browser as the starting point

One repository, clients/ with 51 clients each holding nested projects, internal/ with its own tree, and almost none of it on your disk. Four moves:

  • DepthMiller columns — clients / acme-corp / website / trunk is four glances, not four expand-clicks. Each column filters independently; arrow keys walk the tree.
  • SliceEvery node shows whether you have it fully, sparsely, or not at all, plus a disk meter (18.4 GB of 2.1 TB). In a monorepo that's the most important fact on screen.
  • ProjectsA folder holding trunk/branches/tags is detected as a project — branch switcher, last commits, checkout button — not just another folder.
  • Jump⌘P fuzzy path jump (“acm web” → clients/acme-corp/website), bookmarks, recents, saved searches, and breadcrumbs that are dropdowns to siblings.
  • Roll-upFolders carry status roll-ups — 12M 1C on clients/ — so local work is visible from the root without expanding anything.
  • SparseCheckout dialog is a real working-set editor: per-subtree depth, size estimates, “excluding vendor and media-raw saves 5.5 GB”.

Studio

Strategy: one dial, three audiences
Light + dark · Instrument Sans / Instrument Serif · accent #3746a6

A Simple / Standard / Expert dial in the title bar. It doesn't just hide buttons — it changes row density, vocabulary, column count, and which machinery exists at all. Simple gets 58px rows, “Edited” instead of M, a plain-English change summary and no log. Expert gets 29px rows, mono paths, the diff, the operation log and a status bar. Same layout, same data, three products.

  • LayoutSidebar → change table → inspector, plus an expert-only operation log. Widths and density are driven by the dial.
  • ContentStatus is a word or a letter depending on mode; the inspector shows a plain-language “what changed” summary that promotes to a real diff on request.
  • ModalsThe commit dialog reshapes — Simple drops the options rail and shows a counted summary; Expert shows the full manifest, hooks and bugtraq.
  • MenusThe context menu is the same menu at three depths, with an “more options in Standard mode” footer so nothing feels hidden.

Guide

Strategy: plain by default, technical as a layer
Warm light · Newsreader / Plus Jakarta Sans · accent #1f5c8b

The layout never changes. Everything is written in plain language for everyone, and one “Developer details” switch layers the truth on top: revision numbers, the real svn command under every button, file paths, and a command log dock. Nobody is put in a lesser mode — the expert just sees annotation. Task-first: the page answers “what should I do next?” before it shows a file list.

  • LayoutQuiet nav + a single scrolling column of cards: status hero → needs-you → your changes → coming in → locks. Detail opens in a sheet, never a new screen.
  • ContentEach file says what it means (“You changed how Shelly asks for file status”), not just its status letter. The conflict is explained as two named people's edits, side by side.
  • ModalsRight-hand sheets with a visible 3-step commit flow; the undo dialog offers “save to a file first” as the safer path.
  • MenusPlain verbs, with the literal svn command underneath once developer details are on.

Bench

Strategy: no modes — teach the vocabulary
Warm graphite dark · Manrope / Spline Sans Mono · accent #8b8cf7

No dial, no switch, no second-class mode. Console's three-column density, made teachable: every status reads “Edited · M” — the plain word and the svn letter joined in one badge — jargon carries a dotted underline you can hover for a plain explanation, the log is narrated in English with raw output one click away, and holding ⌘ lights up every shortcut in the UI. A newcomer learns the real words instead of being shielded from them.

  • LayoutIcon rail → file list → right column split between detail and a docked commit composer (no modal, no context switch).
  • ContentRows carry a one-line “what this means”; group headers explain why files are grouped (“held back from sharing”).
  • ModalsReserved for decisions that lose work — the conflict helper lists the three clashes and says which can keep both sides.
  • MenusPlain label, real command, shortcut — all three on every item, plus a “what does Edited mean?” footer.
