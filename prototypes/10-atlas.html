Subversion has no idea what a “project” is

It only stores folders. Shelly adds the idea of a project on top, so a 51-client repository can be navigated by what people actually work on. Here's exactly how a folder becomes a project — in this order:

1 · Someone labelled it A versioned property on the folder gives it a proper name. Survives renames and moves, and everyone on the team sees the same thing. svn propset shelly:project "Acme Website" clients/acme-corp/website
2 · A list in the repository A single file at the root naming project folders and how to group them. One commit, reviewable, good for labelling hundreds at once. /.shelly/projects.yml
3 · It looks like one how this one was found A folder that directly contains trunk — usually with branches and tags alongside — is a project by convention. Nobody has to do anything. detected: trunk + branches + tags
4 · You checked it out Anything you have a working copy of counts as a project to you, whatever the server says.
If none of these apply, there are no projects.

You get plain folders and the explorer works exactly the same. Projects are a lens over directories, never a requirement — and you can always overrule Shelly on any folder: “Treat this as a project” or “This isn't a project”.

The same guess drives the version menu

trunk → “Current work”, branches/* → “Work in progress”, tags/* → “Released”. A project that doesn't use that layout simply doesn't get a version menu.

Detection is per folder, so projects can nest.
