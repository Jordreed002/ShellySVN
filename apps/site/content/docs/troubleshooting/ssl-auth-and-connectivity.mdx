## What to check first

- Whether the repository is reachable outside the app
- Whether the server presents a certificate chain your machine trusts
- Whether stored credentials are valid for the exact repository path

## Good evaluation practice

Validate SSL and authentication behavior early in a rollout, especially for older on-prem SVN infrastructure.

## If prompts repeat

Treat repeated prompts as a signal to investigate certificate trust, URL mismatch, or credential scoping before retrying the same operation indefinitely.

## Specific codes

The [error map](/docs/troubleshooting/error-map) covers the individual codes — authentication failures (`E170001`, `E215004`), connection failures (`E175001`, `E175002` with `E720xxx`/`E730xxx` chains), and certificate verification failures — and what the app shows for each.
